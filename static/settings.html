Projects

    Select a project on the left, or create a new one.

    Identity

    Reference sources

    External reference data joined onto rooms (e.g. dRofus), keyed by name — the name is the join namespace a filter or comparison key writes as "<name>.<label>" (see STRATEGY-SOURCES.md). A project with none configured is a normal state. A source's CSVs are uploaded here and stored server-side as dated snapshots, so each upload is a version a milestone can pin.

    Hierarchy

    Classification tiers, outermost first. Each tier needs a code property and/or a name property. A tier named "Building" powers the building filter.

    Builtin properties

    Canonical property name → each source's raw property name (e.g. canonical "Area" backed by revit's "Fläche"). Only needed when a raw name differs from the canonical one.

    Room label

    Ordered fields shown on each room in the viewer. $name and $id are the room's own name/id; source.Column reads a joined reference source; anything else is a property name.

    Milestones

    Named dates with data snapshots pinned to them. The viewer's milestone dropdown lists these; a pinned model is served from that snapshot instead of its latest, and an unpinned model doesn't appear in the milestone view. Snapshot ids are what's stored on the server.

    Colour plans

    Named room-colouring configs the viewer's colour picker offers. At most one may be active (the picker's default; "No colour" always overrides). All colouring is computed in the browser — the server just stores these. This pass edits property compare plans (compare two room properties, colour by the result). Property names come from the current project's rooms, plus source.Column for a joined reference source's data. Hierarchy tiers are the exception — they read room properties only.
